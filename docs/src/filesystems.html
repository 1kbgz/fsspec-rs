fsspec-rs filesystems¶

fsspec-rs provides Rust-backed filesystems through fsspec classes. Importing fsspec_rs registers the protocols with fsspec:

Filesystem

Protocols

Class

Local filesystem

file-rs, local-rs

fsspec_rs.LocalFileSystem

Amazon S3

s3-rs

fsspec_rs.S3FileSystem

The standard file, local, and s3 registrations remain unchanged.

import fsspec
import fsspec_rs

with fsspec.open("file-rs:///tmp/example.txt", "rb") as f:
    data = f.read()

Local filesystem¶

LocalFileSystem wraps the Rust LocalFs backend, which uses std::fs for local paths. It is marked as a local filesystem (local_file = True) and implements fsspec’s core filesystem operations.

from fsspec_rs import LocalFileSystem

fs = LocalFileSystem(auto_mkdir=True)
fs.pipe_file("/tmp/fsspec-rs/example.txt", b"hello")

assert fs.exists("/tmp/fsspec-rs/example.txt")
assert fs.isfile("/tmp/fsspec-rs/example.txt")
print(fs.info("/tmp/fsspec-rs/example.txt"))

Local paths¶

Direct method calls use normal local paths:

fs.cat_file("/tmp/fsspec-rs/example.txt")

fsspec URLs use file-rs:// or local-rs://:

with fsspec.open("local-rs:///tmp/fsspec-rs/example.txt", "rb") as f:
    print(f.read())

LocalFileSystem._strip_protocol() removes only the Rust-specific local protocols. The file:// and local:// protocols still select fsspec’s Python implementation.

Opening files¶

Supported modes are rb, wb, ab, and xb, plus the aliases r, w, a, and x at the Rust layer. Python wrappers expose binary file objects that implement read, write, seek, tell, flush, close, readable, writable, and seekable.

with fs.open("/tmp/fsspec-rs/out.bin", "wb") as f:
    f.write(b"payload")

with fs.open("/tmp/fsspec-rs/out.bin", "rb") as f:
    f.seek(2)
    print(f.read())

auto_mkdir=True creates missing parent directories for write, append, exclusive-create, and copy operations. With the default auto_mkdir=False, the operating system reports an error if a parent directory is missing.

Local operations¶

Local filesystem methods delegated to Rust include:

  • Listing and metadata: ls, info, exists, isdir, isfile, size

  • Reads and writes: open, cat_file, pipe_file, head, tail, read_text, write_text, touch

  • Directory operations: mkdir, makedirs, rmdir, walk, find, du

  • Mutation and transfer: rm_file, rm, cp_file, copy, mv, get_file, put_file

The cache_type, block_size, and max_blocks options are accepted by open() for API compatibility but do not change local read behavior. Local reads use direct filesystem operations.

S3¶

S3FileSystem wraps the Rust S3Fs backend, which uses Apache Arrow’s object_store crate and runs its async S3 calls through an embedded Tokio runtime. The Python protocol is s3-rs, so it can coexist with s3fs.

from fsspec_rs import S3FileSystem

fs = S3FileSystem(bucket="my-bucket", region="us-east-1")
fs.pipe_file("reports/hello.txt", b"hello")
print(fs.cat_file("reports/hello.txt"))

S3 paths¶

S3FileSystem is constructed for one bucket. Method calls can use keys within that bucket:

fs.ls("reports")
fs.info("reports/hello.txt")

fsspec URLs include the bucket. _get_kwargs_from_urls() extracts constructor options from the URL:

with fsspec.open(
    "s3-rs://my-bucket/reports/hello.txt",
    "rb",
    region="us-east-1",
) as f:
    print(f.read())

Object names are stored internally without a leading slash. Directory entries are S3 prefixes, not real directories; mkdir() and rmdir() are no-ops.

Credentials and endpoints¶

Credential resolution follows this order:

  1. Explicit constructor arguments: key, secret, token, region, endpoint_url, and anon

  2. fsspec.config.conf["s3"], including values populated from fsspec config environment variables

  3. object_store’s own AWS credential chain, such as environment variables, profiles, and instance or task roles

client_kwargs={"endpoint_url": ...} is accepted for compatibility with s3fs. The Rust backend allows plain HTTP when the endpoint starts with http://, as used by local S3-compatible services.

fs = S3FileSystem(
    bucket="benchmark",
    key="minioadmin",
    secret="minioadmin",
    endpoint_url="http://localhost:9000",
    region="us-east-1",
)

Anonymous access is available with anon=True.

Caching reads¶

S3 reads support optional Rust-side cache strategies through cache_type:

cache_type

Behavior

none

Fetch each requested byte range directly.

readahead

Keep one lookahead window for sequential reads.

block

Cache fixed-size blocks with LRU eviction.

all

Fetch the whole object on first read.

 
with fs.open(
    "large/table.parquet",
    "rb",
    cache_type="block",
    block_size=8 * 1024 * 1024,
) as f:
    header = f.read(4096)

block_size defaults to 4 MiB, and the Rust max_blocks default is 32. The Python file wrapper does not forward max_blocks from open(), so callers cannot change it through that method.

Without an explicit cache_type, S3 read mode eagerly loads the whole object into memory. Explicit readahead, block, and none select range-based reads.

S3 operations¶

S3 methods delegated to Rust include:

  • Listing and metadata: ls, info, exists, isdir, isfile, size

  • Reads and writes: open, cat_file, pipe_file, head, tail, read_text

  • Prefix traversal: walk, find

  • Object mutation: rm_file, rm, cp_file

S3 writes buffer object contents in memory before upload. The public API does not support concurrent multipart uploads or signed URLs.
