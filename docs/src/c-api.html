C API reference¶

libfsspec is the shared library that contains the process-wide filesystem registry and the built-in backends. Its interface is fsspec.h. The fsspec_sys crate declares the same interface for Rust.

ABI version¶

FSSPEC_ABI_VERSION is the version the header describes; fsspec_abi_version() returns the version the loaded library was built with. Both are 1. Every vtable and factory struct starts with struct_size and abi_version. Registration fails with FSSPEC_INVALID_ARGUMENT when abi_version differs from the library’s, or when struct_size is smaller than those two fields or larger than 64 KiB. A struct shorter than the library’s is accepted; the missing trailing fields are treated as null.

Strings and memory¶

Arguments are UTF-8 pointer and length pairs and need no NUL terminator. Values that libfsspec returns are owned by the caller and freed with the matching function:

Type

Fields

Free with

fsspec_string

data (NUL-terminated), len (without the NUL)

fsspec_string_free

fsspec_string_list

items, len

fsspec_string_list_free

fsspec_bytes

data, len

fsspec_bytes_free

fsspec_file_info

name, size, file_type, created_ns, modified_ns, extra

fsspec_file_info_free

fsspec_file_info_list

items, len

fsspec_file_info_list_free

created_ns and modified_ns are nanoseconds since the Unix epoch, or -1 when unknown. file_type is FSSPEC_FILE_TYPE_FILE, FSSPEC_FILE_TYPE_DIRECTORY, or FSSPEC_FILE_TYPE_OTHER. extra contains backend-specific fields as alternating key and value strings.

All of these buffers use the platform allocator: malloc on Unix and HeapAlloc(GetProcessHeap(), ...) on Windows. Foreign backends allocate the values they return through vtable callbacks the same way, and libfsspec frees them.

Foreign backends¶

fsspec_fs_from_vtable(vtable, data) wraps an implementation written outside libfsspec as an fsspec_fs *, and fsspec_file_from_vtable(vtable, data) does the same for an open file. Both copy the vtable, pass data to every callback, and return null with the error message set on failure.

fsspec_fs_vtable:

Field

Description

struct_size, abi_version

As for factories.

protocol

NUL-terminated, comma-separated protocol names, such as "file,local".

root_marker, sep

NUL-terminated strings; null uses the defaults.

ls, info, rm_file, cp_file, mkdir, rmdir, open

The FileSystem primitives. A null callback makes its operation return FSSPEC_NOT_SUPPORTED. Other operations, such as cat_file and exists, are derived from these.

release

Called with data when the last handle is released.

strip_protocol, unstrip_protocol, cat_file, pipe_file

Optional, after release. A backend that overrides these in Rust keeps its own behaviour across the ABI; null uses the derived defaults.

fsspec_file_vtable has read, write, seek, flush, size, info, commit, discard, and release. A null read, write, seek, or info returns FSSPEC_NOT_SUPPORTED; a null size reports -1; a null flush, commit, or discard succeeds without doing anything. release is called on close.
